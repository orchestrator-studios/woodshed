Ledger Phase 1 — Sessions on the Board

Make BotBeam the system of record for sessions, and make its board view obey the Ledger Book's cheat sheet: the sessions listed are exactly the ones Cliff wants listed (Rule 1), the glyphs are right (Rule 2), and archiving is one click. Events and work products ship as empty columns this phase — the record plane comes later.

phase 1 · 2026-09-12 · governs: The Ledger Book rev 14 · repos: botbeam + woodshed

Prime directive: don't break BotBeam. Every change is additive — new tables, a new /ledger router, a new frontend view. Devices, beams, lockboxes, and memories are untouched. The old pushed board (board.py → "Ledger" display) keeps working until the cutover step, so there is never a moment without a board.
Work items — in dependency order; all additive
#ChangeWhereNotes
B1 Session store. One new table, ledger_sessions, holding exactly the Book's stored facts: id (CC uuid, PK) · user_id · workspace_id · machine · label · first_seen · last_event_at · last_prompt_at · last_run_at · ended_at · ever_prompted · archived_at · transcript_missing_since. No status columns — statuses are never stored. models.py tables auto-create on startup, so deploy is a restart; no migration tooling needed
B2 Derivation service. A pure function facts → {status, activity, relevant}, implementing the cheat sheet's rules verbatim. Two windows in settings: LEDGER_SILENCE_WINDOW (default 15 min) and LEDGER_RUN_WINDOW (default 2 min); expiry at 3 consecutive sweep misses. The mutating-tool list (Write · Edit · NotebookEdit · Bash · PowerShell) lives here — service policy, per the Book. services/ledger_service.py unit-test the cascade directly: 9 transition rows = 9 test cases
B3 The /ledger router. Five endpoints from the Book, sessions plane only: POST /ledger/sessions/{id}/events (upsert facts from a hook signal, return the full Session representation) · POST …/archive · …/unarchive (409 if active; batch form with prefixes / all+keep) · POST /ledger/sessions/sweep-report · GET /ledger/sessions (filters: status, machine, relevant) · GET /ledger/board → {sessions, events: [], products: [], as_of}, relevant sessions only, active first. routers/ledger.py existing JWT bearer + get_current_user; all rows scoped to user_id; server stamps every timestamp
B4 Board view in the frontend. A "Sessions" view rendering GET /ledger/board: card per session (label, workspace, machine, relative last-activity) with the Rule 2 glyphs — solid green / +⚡ / hollow ring / gray — an Archive button on dormant cards, and batch clear ("archive all dormant"). Events and products columns render, empty. Refresh: WS ledger message broadcast on every session write → view refetches (poll fallback 10 s). frontend/src/components/ this replaces the content of the old Ledger display; the Device machinery is not touched
B5 Test reset. POST /ledger/admin/reset — truncates ledger_sessions (and later ledger tables), current user only, enabled by a settings flag. This is the "clear everything" button for the test protocol. routers/ledger.py dev convenience; keep behind LEDGER_ADMIN_RESET=true
B6 Deploy without breaking anything. Restart backend with the new code (new table auto-creates). Smoke before/after: login, beam to default display, lockbox stash/retrieve, memory upsert — all unchanged. uvicorn :4888 BotBeam has no cloud deploy yet; "deployment" = the running instance restarted on the new build
Explicitly out of scope this phase: POST /ledger/log, streams, events, products, search, orientation/index, attribution, and any change to beams, lockboxes, or memories. The board's events/products columns stay empty until phase 2.
Work items — hooks become transmitters; board.py retires from session duty
#ChangeWhereNotes
W1 Hook transmitter. One small script, session_event.py: reads the hook payload from stdin, POSTs it to /ledger/sessions/{id}/events with the bearer token, exits 0 always — a hook must never block a session; on service failure it drops the signal (the derivation model absorbs gaps). PostToolUse debounce: skip the post if one was sent within run-window/2 (tiny per-session stamp file in temp) — lossless, since facts are max-timestamps; turns a 50-tool burst into ~2 posts. skills/ledger/scripts/ token + base URL from ~/.config/orchestra/botbeam.json
W2 Rewire the five hooks. SessionStart · UserPromptSubmit · Stop · SessionEnd · PostToolUse (matcher: all tools) → session_event.py, async. They stop calling board.py. ~/.claude/settings.json per machine: cmr-nuc and the laptop
W3 Sweep reporter. sweep_report.py: list this machine's known sessions (GET /ledger/sessions?machine=…), check each transcript's presence under ~/.claude/projects/, POST …/sweep-report. Scheduled task replaces LedgerBoardSweep's command, same 5-minute cadence. skills/ledger/scripts/ + schtasks observes transcripts, never writes them
W4 Retire board.py from sessions. No hook calls it, no sweep runs it, it no longer renders or beams the board; sessions/*.json in the ledger root is frozen (no import — the test starts from a clean store). Keep the file until the phase closes, then delete. skills/ledger/scripts/board.py the "Ledger" display device can be retired or repurposed after cutover
W5 Skill update — sessions verb only. /ledger sessions (list · archive · unarchive) becomes API calls to /ledger/sessions; log / recall / review / stream stay on the v1 files this phase. Drop the board-beaming instructions. skills/ledger/SKILL.md judgment stays; file mechanics for sessions go
Order: B1–B3 land and deploy first (BotBeam accepting signals while the old board still runs) → W1–W2 flip the hooks → B4 gives the view → W3 sweeps → cutover: W4 retires the old board. At every step there is a working board somewhere.
